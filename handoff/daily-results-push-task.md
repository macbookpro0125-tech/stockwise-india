Daily results push for Jocular Insights (NSE stock research site jocularinsights.in; code in ~/Projects/stockwise-india, branch screeners-home). Read the last 20 lines of handoff/LOG.md first. Why: Search Console shows company results pages are the pages that reach Google's first page, so each day's new results pages are pushed while people search for them.

1. Run `node scripts/results-day.mjs` in the repo. It reads the live /results page and handoff/indexing-state.json and prints JSON: `google` (up to 10 URLs not yet requested), `bing` (up to 100 not yet submitted), `shorts` (candidate companies for today's Shorts, best first, with spares; empty between seasons). If google and bing are both empty (between results seasons), write one line to handoff/LOG.md saying nothing new, commit it, and stop.

2. Google (built-in browser, the jocularinsights@gmail.com Search Console, already signed in; never type a password; if a sign-in page appears, stop this step and say so): open https://search.google.com/search-console?resource_id=https%3A%2F%2Fjocularinsights.in%2F. For each URL in `google`: click the search icon at the top, select all, type the URL, Enter, wait ~10 s; if it says "URL is on Google" skip it; otherwise click REQUEST INDEXING and wait 20–40 s for "Indexing requested", then Dismiss and wait 2 s before the next (clicking too soon re-requests the previous page). Stop at "Quota Exceeded" (about 10 per rolling 24 h). Record the ones accepted: `node scripts/results-day.mjs --mark google URL…`.

3. Bing and the other IndexNow engines (since 14 Nov; no browser): `node scripts/indexnow.mjs --results-day` sends the day's `bing` URLs to IndexNow and records them as sent. If it says the key file isn't live, say so (the push that adds it hasn't happened). Once a week (Mondays) also run `node scripts/indexnow.mjs --sitemap lists screens sectors pages` so changed list and screen pages are recrawled.

4. Two Shorts a day (the owner asked on 13 Nov), in the voiced style (Michael's voice, live site cards, see scripts/shorts-voice/README.md). Slots on YouTube: **A = 6 pm IST (3:30 PM in Studio's default GMT+3)** and **B = 9 pm IST (6:30 PM GMT+3)**. On 14 and 15 Nov 2026, slot A is already taken (BEL, Sterlite), so make one new Short for slot B those days; otherwise make two, using the first entries of `shorts` (spares below them if one fails).
   For each new Short:
   a. `node scripts/shorts-voice/from-results.mjs SYMBOL` — reads the live results page and the company's public data, writes ~/Projects/files/shorts-v2/<symbol>-<quarter>/spec.json (what Michael says and shows) and post.txt (YouTube title and description, Instagram caption). If it says "not a two-figure story" (a loss quarter), take the next spare.
   b. Read spec.json and post.txt. Check every figure against the live pages (https://jocularinsights.in/stock/SYMBOL/results/<quarter> and /stock/SYMBOL). You may reword a line so it reads naturally, but never change a figure, and never use buy/sell/target words.
   c. `node scripts/shorts-voice/build.mjs <spec.json> --stills`, then look at the stills (contact sheet: `cd <dir>/stills && ffmpeg -y -loglevel error -pattern_type glob -i 'l*.jpg' -vf "scale=300:533,tile=6x2" -frames:v 1 ../sheet.jpg`): words must not overlap the small source line, nothing important in the right ~150 px. Fix the spec and repeat if needed.
   d. `node scripts/shorts-voice/build.mjs <spec.json>` (about 12 minutes each; run in the background, one after the other, never two at once) → <dir>/<key>.mp4.
   e. YouTube, with Claude in Chrome (the owner's Chrome, Jocular profile; if Chrome isn't connected, skip uploads and say so; the owner may need to open the Claude side panel there and sign in with the same Claude account as the app): copy the mp4 into ~/Projects/files/shorts-upload/ (delete it afterwards), open YouTube Studio for the Jocular Insights channel, Upload videos, upload via the hidden file input, then title and description from post.txt. No #hashtag at the end of the title (its pop-up swallows the next click) and never press Escape in the upload window (it closes it; the draft is kept under Content → Shorts → Edit draft); after typing the description click the "Details" heading to close the hashtag pop-up. Mark "No, it's not made for kids", Next ×3, Visibility → Schedule: today (tomorrow if the time has passed), pick the slot's time from the time list → Schedule. No library music (the video has its own soft beat under the voice). Record: `node scripts/results-day.mjs --mark short SYMBOL`.
   f. Instagram (@jocular_insights, same Chrome window; Instagram's website can't schedule, so Reels are posted by this run in the morning and by the evening task `instagram-evening` at ~9 pm IST, from ~/Projects/files/shorts-v2/instagram-queue.json):
      - Add each new Short to the queue: `{"date": today, "slot": "morning" or "evening", "mp4", "caption": its post.txt, "cover": its stills/l04.jpg, "posted": null}` — slot A's video is "morning", slot B's "evening" (on 14/15 Nov the queue already has the morning one).
      - Now post today's "morning" entry, if not posted, as below, and set its "posted" to the Reel link.
      - How to post a Reel (if Instagram shows a login page, skip and say so; never type the password): copy the mp4 and the cover jpg into ~/Projects/files/shorts-upload/; https://www.instagram.com/ → left bar "+ Create" → upload the mp4 through the hidden file input → OK on "Video posts are now shared as reels" → crop icon (bottom-left) → "Original" (otherwise it's cut square) → Next → Cover photo: "Select From Computer" (hidden file input) with the cover → Next → caption: the INSTAGRAM CAPTION from the caption file → "Add AI label" ON (Michael's voice is AI-made) → Share; wait ~30 s for "Your reel has been shared"; the link is the newest /reel/ on https://www.instagram.com/jocular_insights/reels/. Delete the copies in shorts-upload.

5. Add one line to handoff/LOG.md (date; how many Google requests accepted; Bing count; each Short's company, story, YouTube link and slot, and the morning Reel link) and commit handoff/LOG.md and handoff/indexing-state.json only (git fetch first; other tools edit this repo; never push; end the commit message with "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>").

6. Finish with a 3-line plain summary for the owner (simple English; they read it on their phone). Never invent figures; no buy/sell/target words (SEBI); never publish anything but the day's Shorts (YouTube) and the morning Reel from the queue; never change account settings.
